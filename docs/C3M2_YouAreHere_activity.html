Situation

Reviewed, so let it act?

You have been asked to lead supply chain transformation at Sample Enterprise Goods, a manufacturer and distributor of household and personal-care consumables. Ten weeks ago the supply planning team began a pilot of exception alerts. The supply planners read the alerts and decide what to do: move stock between distribution centers, expedite a truck, or leave the plan alone.

The pilot team has circulated its summary. The supply planning manager now wants to go one step further. For each alert that calls for an expedite, the system would queue the expedite, so that planners can act faster.

Exception alert
A warning that an order, shipment, or stock position is off plan and may need a decision.
Alert type
One rule that raises one kind of alert, such as a purchase order line that is past due.
Expedite
Pay for faster freight so that a shipment lands sooner.
Queue an expedite
The system prepares the faster-freight request and holds it ready, so a planner does not build it by hand.

    Each option was a sound move for a manager who reads “reviewed” as “checked”. None began by asking how far software should go on each response, given the review that people can actually perform at this volume.

    That read has two parts. The first sizes the alert stream against the minutes people have, so that the alerts that reach a person are ones the person can investigate and act on. The second sets, response by response, how much the software does and how much a person decides, and tests whether the review attached to each is real. It has to be in place before any response can be automated, funded, or scoped.
